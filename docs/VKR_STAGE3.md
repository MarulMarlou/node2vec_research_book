# ВКР — этап 3: веб-интерфейс и book-to-book протокол

**Статус:** программный прототип, а не законченная ВКР. Выполнены синтетические проверки. Настоящий Book-Crossing, жанровое обогащение и научная серия экспериментов ещё не проверены.

## Источник данных

Официальное описание Book-Crossing: https://grouplens.org/datasets/book-crossing/ . ВКР должна ссылаться на первичную работу: Ziegler C.-N., McNee S. M., Konstan J. A., Lausen G. *Improving Recommendation Lists Through Topic Diversification*, WWW 2005, DOI 10.1145/1060745.1060754.

Требуются исходные `BX-Books.csv` и `BX-Book-Ratings.csv` в `data/raw` (исходные CSV — semicolon/latin-1). В GitHub этих CSV нет. `BX-Users.csv` не требуется для текущего контура. Жанры подключаются при наличии отдельного CSV со столбцами `isbn,genre,source_url`. Пустой source_url запрещён.

## Функции веб-интерфейса

- Поиск и выбор книги по названию или ISBN, включая одноимённые книги с разными ISBN.
- Node2Vec-косинусное сходство, число рекомендаций, управляемое число кандидатов.
- Два типа пути: `shortest` (кратчайший допустимый) и `informative` (оценка значимости типа, редкости и длины).
- `posthoc` сохраняет порядок Node2Vec; `rerank` объединяет баллы с информационным скорингом пути, параметр alpha от 0 до 1.
- Русский текст, путь и визуализация только подтверждённых рёбер со сведениями об источнике; отсутствие пути отображается явно.
- Metadata/Jaccard как контрольный метод, покрытие объяснениями, время построения.
- Раздельные таблицы метрик user-to-book и косвенной book-to-book оценки.

## Корректная оценка похожих книг: proxy на предпочтениях

`src/vkr_book_eval.py` задаёт явный, воспроизводимый сравнительный протокол:

1. Выделить train/test **до построения графа** и обучения Node2Vec.
2. Для каждого пользователя с тестовыми положительными оценками выбрать до 3 понравившихся train-книг.
3. Рекомендовать новые книги, исключая все уже оценённые пользователем в train.
4. Использовать оценку кандидата как максимум сходства с исходными книгами; сравнить Node2Vec и Jaccard на *одинаковых* кандидатах.
5. Рассчитать P@k, R@k, F1@k, NDCG@k, MRR и покрытие. Необслуженные пользователи учитываются в знаменателе с нулевыми результатами.

**Ограничение:** этот proxy измеряет восстановление отложенных положительных предпочтений, **не является прямой экспертной оценкой семантического сходства пар книг**, не является хронологическим прогнозом и подвержен неполноте меток. Финальные гиперпараметры нельзя выбирать на итоговом test — потребуется validation.

## Артефакты

`results/metrics/vkr_pipeline_report.json` дополнен `book_to_book_proxy_holdout`, исходными хешами SHA-256 двух CSV (`input_sha256`) и хешами графа, train/test, эмбеддингов и списка ID (`artifact_sha256`). `src/vkr_dashboard.py` проверяет их соответствие перед отображением выдачи. SHA-256 обеспечивает контроль совпадения файлов между этапами, но не подтверждает подлинность источника.

Для автоматизированной проверки используются синтетические Book-Crossing CSV, а не реальные научные наблюдения. В CI предусмотрено 32 теста (включая тест данных Plotly без Streamlit-сервера); зелёный CI не заменяет реальный запуск UI в браузере. Скриншоты реального интерфейса после развёртывания ещё не сделаны.

## Остаётся для ВКР

- Проверить настоящие CSV: источник, размеры, аномалии и сохранённые SHA-256.
- Обогатить граф жанрами из проверяемого источника; убедиться, что ISBN правильно сопоставлены.
- Провести эксперименты с реальной моделью, train/validation/test, несколькими seed; сравнить параметры, качество, покрытие, время и ресурсы.
- Выполнить отдельные эксперименты по изменению ранжирования при разных alpha/method и по faithfulness после удаления рёбер и повторного обучения при фиксированном seed.
- Провести браузерный smoke-тест Streamlit и собрать скриншоты; оформить научную часть, рисунки, таблицы и приложения.

## Автоматическая проверка Streamlit

Вторая задача GitHub Actions устанавливает `requirements-vkr-app.txt` (Streamlit 1.66.0 и PyArrow 16.1.0 для совместимости с NumPy 1.26.4) и запускает `tests/test_vkr_streamlit_smoke.py` через официальный `streamlit.testing.v1.AppTest`. Проверяется выполнение страницы, загрузка артефактов, формирование рекомендаций и наличие вкладок. Этот headless-тест **не заменяет** ручное открытие интерфейса в браузере.

Команда для smoke-теста после установки зависимостей:

```bash
python -m pytest -q tests/test_vkr_streamlit_smoke.py
```

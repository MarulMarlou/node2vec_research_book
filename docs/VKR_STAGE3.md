# Дополнительный прототип: рекомендации и объяснения (Streamlit)

**Статус на 14.10.2026:** функциональность реализована, автоматизированно проверена на синтетическом наборе, основной конвейер проверен на реальном Book-Crossing, а `quick` также успешно запущен локально на Windows. Ручной приёмочный тест веб-интерфейса с браузерными скриншотами заказчика ещё не подтверждён. Это **дополнительная часть ВКР**, а не условие завершения первых двух этапов.

[README](../README.md) · [Windows-инструкция](VKR_WINDOWS.md)

## Возможности интерфейса

- Выбор исходной книги по названию/ISBN с сохранением различий между изданиями.
- Рекомендации похожих книг по косинусной близости Node2Vec.
- Два способа объяснения: **кратчайший допустимый путь** и **информативный ранжированный путь** с ограниченным поиском.
- Режимы **posthoc** (объяснение без изменения ранжирования) и **rerank** (учёт оценок информативности при ранжировании).
- Русский фактологический текст, визуализация графового пути и реальные сведения об источнике каждого ребра.
- Сопоставление с контрольным metadata/Jaccard; отдельные показатели user→book и косвенного book→book proxy.
- Проверка соответствия модели, исходного графа, сохранённых ratings и отчёта по SHA-256 до отображения результатов.

## Запуск

После размещения `BX-Books.csv` и `BX-Book-Ratings.csv` в `data/raw`:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_vkr_windows.ps1 -Mode quick
powershell -ExecutionPolicy Bypass -File .\scripts\run_vkr_windows.ps1 -Mode app -SkipInstall
```

Откройте http://localhost:8501. Выход — Ctrl+C. При обновлении основного графа повторите `quick` или `main` целиком: интерфейс намеренно отклоняет несогласованные артефакты.

## Фактологическое основание объяснений

Метод строит пути книга–автор–книга, книга–издательство–книга, книга–жанр–книга (только после реального обогащения), книга–пользователь–книга (только допустимые положительные рейтинги train), а также ограниченные пути длиной до четырёх рёбер. Он использует исходный `MultiDiGraph` и проверяет существование каждого ребра.

**Ограничение:** существование пути по KG подтверждает общую характеристику/взаимодействие, но **не доказывает причинное участие этого пути** в Node2Vec similarity score. Для информативного метода `truncated=true` обозначает достижение бюджета поиска: глобальная оптимальность не гарантируется. `explanation_coverage` считается для конкретной выдачи, не для всего каталога.

## Book→book preference proxy и пользовательские метрики

`src/vkr_book_eval.py` измеряет восстановление отложенных положительных пользовательских предпочтений по ранее понравившимся книгам. Это полезная косвенная оценка, но **не экспертный gold-standard семантической похожести**. Не смешивайте показатели данного сценария с user→book.

## Проверки и ограничения

- Исходные данные проверены на реальном Book-Crossing в основном конвейере, а также в локальном Windows `quick`.
- В GitHub Actions запускаются отдельные unit/integration-тесты и `streamlit.testing.v1.AppTest`; это headless-проверка, **не снимки браузера**.
- Проверки каталожного покрытия объяснениями, времени построения путей на полной выборке, интерпретируемости для пользователей и faithfulness с удалением рёбер и **переобучением** модели ещё предстоят.
- Жанровые рёбра появятся только после отдельного проверяемого обогащения. Без них нельзя утверждать, что рекомендации опираются на жанры.

Файлы интерфейса: `src/vkr_app.py`, `src/vkr_dashboard.py`. Методы поиска: `src/vkr_explain.py`; baseline и метрики: `src/vkr_book_eval.py`, `src/vkr_recommend.py`.

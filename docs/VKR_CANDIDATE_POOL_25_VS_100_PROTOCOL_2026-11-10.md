# ВКР: новый контролируемый эксперимент candidate pool 25 vs 100

**Статус на 10.11.2026:** код эксперимента подготовлен и проверяется синтетическими CI-тестами; **реальные результаты этого нового сценария на Book-Crossing ещё не получены**. Методика разработана по итогам [проверенного split 2092](VKR_STAGE3_CANDIDATE_CEILING_2026-11-10.md): 81/120 пользователей не имели ни одной положительной test-книги среди исходных 25 кандидатов, хотя все 120 имели такие книги в доступном модельном каталоге.

## Цель

Проверить, улучшится ли фактическая выдача при переходе от 25 к 100 кандидатам, **отделив** изменение набора потенциальных рекомендаций от подбора метода объяснения/коэффициента alpha.

## План эксперимента

Скрипт: \`src/vkr_candidate_pool_study.py\`. Windows mode: \`explanations-pool-compare\`.

- **Новый split seed=2102**, без повторного использования уже просмотренных 2042, 2052, 2062, 2072, 2082 и 2092; максимум 150 пользователей и 1000 книг в обучающем подграфе.
- **ОДНА** train-only модель Node2Vec для обоих пулов: заранее фиксированы dimensions=64, walk_length=20, num_walks=4, epochs=3, p=q=1, window=3, model seed=43. Все методы используют тот же исходный граф, те же эмбеддинги и неизменный порядок косинусного сходства до posthoc/rerank.
- До 100 подходящих validation-пользователей, до 100 test-пользователей. Их выбор определяется одним \`split_seed\` и одинаков для обоих размеров пула.
- На **validation отдельно** оцениваются 8 конфигураций (\`shortest/informative\`, \`posthoc/rerank\`, α=0,2/0,5/0,8) для **каждого** пула — всего 16 настроек **постобработки одной модели**, а не 16 обучений.
- До просмотра test фиксируются два победителя по validation NDCG@10 (и P@10 при равенстве). На test проверяются **только заранее выбранные**:
  1. **Pool25 + лучший конфиг Pool25** (контроль);
  2. **Pool100 + тот же конфиг Pool25** — **чистое влияние размера пула** при фиксированном методе и α;
  3. **Pool100 + лучший конфиг Pool100** — сравнение **целых validation-настроенных pipeline** (здесь может отличаться и метод/α).
- Для обоих сравнений с baseline Pool25 вычисляются **попарные разности по одним и тем же пользователям** и условные 95%-е percentile-bootstrap интервалы (3000 повторов с зафиксированными seed). Исходные User-ID в CSV **не сохраняются**.
- Записываются \`candidate_ceiling\` (каталог, top25, top100, фактический выбранный пул), NDCG@5/10/20, P/R/F1, MRR, доля объяснений, средняя длина пути, частота усечения, а также **время построения объяснений для всех кандидатов пула**, а не только top10. При расширении пула ожидаем больше вычислительных затрат, но заранее не предполагаем улучшение NDCG@10.

**Ни один тестовый рейтинг не используется для формирования каталога, первоначального cosine-пула, поиска путей, обучения эмбеддингов или выбора лучшей конфигурации.** Held-out метки присутствуют только при расчёте диагностик/метрик на заранее выделенном test.

## Запуск на Windows

После локального сохранения несохранённых файлов:

\`\`\`powershell
git switch feature/vkr-stage1-typed-graph-holdout
git pull --ff-only origin feature/vkr-stage1-typed-graph-holdout

powershell -ExecutionPolicy Bypass -File .\scripts\run_vkr_windows.ps1 -Mode tests -SkipInstall
powershell -ExecutionPolicy Bypass -File .\scripts\run_vkr_windows.ps1 -Mode explanations-pool-compare -SkipInstall
\`\`\`

Результаты: \`results/candidate_pool_study/\`:

- \`candidate_pool_study_report.json\` — общий протокол, источник SHA256, два validation-выбора, три заранее заданных test-метрики и оба условных bootstrap-анализа;
- \`candidate_pool_validation_grid.csv\` — 16 настроек по validation с обозначением \`candidate_pool\`;
- \`candidate_pool_test_fixed_configuration_deltas.csv\` — **100@fixed25 − 25@fixed25**, парные метрики без User-ID;
- \`candidate_pool_test_selected_pipeline_deltas.csv\` — **100@best100 − 25@best25**, парные метрики без User-ID;
- \`train_only_node2vec/\` — воспроизводимые эмбеддинги одного общего обучения.

Весь \`results/candidate_pool_study/\` исключён из Git. **Пользовательские ID, исходные оценки и индивидуальные CSV-результаты следует хранить локально и не публиковать открыто.**

## Предварительные ограничения

Результаты будут относиться только к ограниченному графу и единственному split/model seed; парные bootstrap-CI условны относительно выбранной когорты пользователей. Сравнение двух отдельно настроенных pipeline не выделяет отдельно эффект размера пула — **для этого предназначено fixed-configuration сравнение**. Увеличение пула не равно улучшению алгоритма получения кандидатов при неизменном размере: для такого исследования отдельно нужны методы, сравнимые при фиксированном бюджете top25.

Оставшаяся обязанность этапа 1 — получить подтверждённые жанровые факты с provenance, оценить покрытие и провести отдельную абляцию «с жанрами/без жанров». Путь к реальному масштабированию на полный каталог также остаётся исследовательской задачей.

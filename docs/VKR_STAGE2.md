# Этап 2. Исследование и реализация алгоритмов построения эмбеддингов

**Статус на 14.10.2026:** реализован Node2Vec, есть первый реальный эксперимент и воспроизводимая процедура train/validation/test. **TransE для нового типизированного графа пока не интегрирован; серия требуемых сравнений не проведена полностью.**

[README](../README.md) · [Windows](VKR_WINDOWS.md) · [Состояние сдачи](VKR_MILESTONES_1_2.md)

## 1. Node2Vec

В `src/vkr_recommend.py` реализованы взвешенные случайные блуждания второго порядка с параметрами `p` (возврат) и `q` (исследование новой окрестности). Алгоритм обучает `gensim.Word2Vec` Skip-gram с отрицательным сэмплированием; эмбеддинги строятся на **обучающем графе** после разбиения данных. Для ускорения кэшируются распределения переходов между парами соседних узлов; для воспроизводимости используются `seed`, один worker и стабильный хеш строк.

Для оценки близости книг используется косинусная мера между эмбеддингами. Дополнительный контроль metadata/Jaccard использует пересечения авторов, издательств и подтверждённых жанров, **но не обучает эмбеддинги**.

## 2. Два различных экспериментальных сценария

### Демонстрационный сквозной запуск

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_vkr_windows.ps1 -Mode main
```

Подготовка и обучение модели на train, затем оценка user→book и косвенной book→book полезности на test, сохранение модели. По исследовательскому подграфу (до 1 000 пользователей, 5 000 книг) получены следующие **первые результаты одной конфигурации**:

| Метрика | Значение |
|---|---:|
| Размерность эмбеддингов | 64 |
| `p`, `q` | 1,0; 1,0 |
| Длина/число блужданий | 20 / 4 |
| Эпохи | 3 |
| NDCG@10 для user→book | **0,0396** |
| NDCG@10 для book→book preference proxy, Node2Vec | **0,0262** |
| NDCG@10 для book→book preference proxy, Jaccard | **0,0303** |
| Время обучения в контрольной среде | ~10,38 с |

В данном опыте контрольный Jaccard **выше** Node2Vec по косвенному NDCG@10; результат отражён без коррекции. Эти цифры не демонстрируют превосходства Node2Vec и **не подходят для выбора параметров по test**. Подробнее: [зафиксированный эксперимент](VKR_REAL_BOOK_CROSSING_2026-10-14.md).

### Подбор параметров с независимым test

`src/vkr_embedding_study.py` выполняет:

1. Сохранение test, затем выделение validation только из train-подмножества.
2. Отбор пользователей/книг по **train**, чтобы не использовать отложенные метки при построении графа.
3. Обучение моделей с разными конфигурациями/seed **на одном train-графе**.
4. Выбор лучшей конфигурации по `validation_ndcg@10`; при равенстве — по `validation_p@10`, далее по фиксированному порядку конфигурации/seed, независимо от времени запуска.
5. **Однократную** оценку выбранной модели на независимом test.

```powershell
# Три варианта p/q на небольшом графе
powershell -ExecutionPolicy Bypass -File .\scripts\run_vkr_windows.ps1 -Mode study-quick -SkipInstall

# 12 конфигураций × 3 seed = 36 опытов Node2Vec
powershell -ExecutionPolicy Bypass -File .\scripts\run_vkr_windows.ps1 -Mode study-full -SkipInstall
```

Файлы в `results/study/`: `train.csv`, `validation.csv`, `test.csv`, `training_knowledge_graph.graphml`, `selected_embeddings/`, `embedding_experiments.csv`, `study_report.json`. **Выполнение `study-full` ресурсоёмко** и не равно сравнению с TransE.

Пилот на реальном Book-Crossing, до 150 пользователей и 1 000 книг, split seed=2027: train=5 166; validation=556; test=693. Из трёх p/q лучший по validation NDCG@10 вариант `p=q=1`: validation=0,009406, test=0,015765. Эти цифры **не сопоставляются напрямую** с демонстрационным train/test: другое разбиение и экспериментальный протокол.

## 3. Что оценивается

**User→book:** по эмбеддингу пользователя выдаются книги, ещё не оценённые им в train. Precision@k, Recall@k, F1@k, NDCG@k, MRR сравниваются с отложенными положительными оценками.

**Book→book proxy:** выбираются до трёх положительно оценённых пользователем train-книг; по максимальному сходству с ними ранжируются новые книги на одинаковом наборе кандидатов для Node2Vec и Jaccard. Релевантность — положительные книги из test. Это измеряет восстановление предпочтений, **не экспертную семантическую близость двух книг**. Неизвестные оценки не следует трактовать как достоверно отрицательные.

Обе схемы должны сопровождаться размером подвыборки, seed, параметрами модели, длиной выдачи и покрытием. Нельзя подбирать параметры на финальном test.

## 4. Состояние TransE

В старом коде есть `src/transe_runner.py`, но он относится к прежнему конвейеру и **не является интеграцией TransE в новый типизированный граф**. Нынешний модуль исследования эмбеддингов обучает только Node2Vec. Это принципиально: в календарном плане стажировки ожидается сравнение Node2Vec и TransE и не менее 30 опытов. Серия из 36 *одних только Node2Vec* эту часть полностью не закрывает.

Следующие действия: получить triplet-формат `(head, relation, tail)` из `MultiDiGraph`, обучить TransE только на train-графе; задать одинаковый candidate pool, validation/test split, набор seed и метрики для честного сравнения; сформировать таблицы и графики влияния параметров/времени/качества. Возможность положительных/отрицательных рёбер и смысл ratings в разных моделях необходимо описать отдельно.

## 5. Новая реализация TransE и сравнительный протокол

Новый `src/vkr_transe.py` обучается **не на старых файлах `edges.csv`**, а на типизированных триплетах `(head, relation, tail)` актуального KG. Реализованы filtered negative sampling с сохранением типов сущностей, margin-ranking loss, параметры `dimensions`, `epochs`, `batch_size`, `learning_rate`, `margin` и `seed`. Для пользовательских рекомендаций используется трансляционный скоринг `-||u + r_rated - book||₂`, а для Node2Vec — косинусное сходство; каталоги кандидатов и отложенные рейтинги совпадают.

В `src/vkr_compare_embeddings.py` отдельный сценарий `train / validation / test` выделяет **также явные рейтинги 1–6** в validation/test. Это позволяет вычислять **ROC-AUC только на наблюдавшихся положительных (7–10) и низких (1–6) рейтингах** с указанием числа пользователей, имеющих оба класса. Unknown/unrated **не принимаются автоматически за отрицательные**. Выбор конфигураций — по validation NDCG@10, итоговый test — только после выбора. Для остальных метрик сравнения предусмотрены k=5,10,20.

```powershell
# Пробный сравнительный сценарий: два Node2Vec и два TransE
powershell -ExecutionPolicy Bypass -File .\scripts\run_vkr_windows.ps1 -Mode compare-quick -SkipInstall

# Полная сетка: (12 Node2Vec + 9 TransE) × 2 seed = 42 запуска
powershell -ExecutionPolicy Bypass -File .\scripts\run_vkr_windows.ps1 -Mode compare-full -SkipInstall
```

Выход: `results/comparison/comparison_experiments.csv`, `comparison_report.json`, отложенные train/validation/test, выбранные эмбеддинги обеих моделей. **Не переносите результаты** из старого `src/transe_runner.py` и `results/plots/tsne_best_transe.png` в этот протокол.

**Текущее состояние:** сравнение реализовано в коде и покрыто автоматическими тестами на синтетических примерах; **фактическая реальная серия ≥30 запусков и её обобщение пока не выполнены**. Результаты одного случайного seed/подграфа не являются утверждением научного превосходства.

## 6. Границы результата

Полностью законченная научная оценка требует серии seed и гиперпараметров, анализа времени/памяти и статистики устойчивости, сравнения с TransE на сопоставимом протоколе, а затем исследования влияния объяснений/переранжирования. Внешние жанры и исследования faithfulness пока не завершены. Более поздние функции объяснений уже доступны как **демонстрационный прототип** — [см. интерфейс](VKR_STAGE3.md).

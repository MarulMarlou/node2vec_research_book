## 1. Жанровое обогащение графа: реализация и ограничения

Файл `src/vkr_genre_enrichment.py` позволяет получить небольшое количество предметных меток **из конкретных записей Open Library по ISBN**, а не по похожести названия. На каждый внешний факт сохраняется HTTPS-ссылка на издание или произведение Open Library.

**Важно:** поля `subjects` Open Library — это предметные рубрики, **не строгий экспертный gold-standard жанров**. Программа переносит в `genre` только точные совпадения с **закрытым белым списком** рубрик: `Science fiction`, `Fantasy`, `Mystery`, `Romance`, `History`, `Poetry` и т. п. Неизвестные предметные рубрики остаются неразмеченными. Обязательна проверка соответствия ISBN конкретному изданию; поисковая выдача по названию не используется.

**Соблюдение правил источника:** Open Library [прямо запрещает использовать публичное API для массового скачивания книг](https://openlibrary.org/developers/api), рекомендует офлайн-дампы и ограничивает частоту запросов. Поэтому новый режим обрабатывает **не более 25 ISBN за запуск**, делает не чаще одного нового запроса в секунду, сохраняет JSON в локальном кэше и требует реальный контакт в `User-Agent`. При необходимости массового обогащения следует использовать их [bulk dumps](https://openlibrary.org/developers/dumps) или предварительно подготовленный верифицируемый CSV, а **не** запускать публичное API в бесконечном цикле.

### Как получить небольшую проверяемую выборку (Windows)

Сначала соберите обычный граф, чтобы в `data/processed` появился список **только обучающих** взаимодействий:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_vkr_windows.ps1 -Mode quick -SkipInstall
```

Теперь запустите контролируемое обогащение **с собственным настоящим контактным email**, не включая его в Git:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_vkr_windows.ps1 -Mode genre -SkipInstall -ContactEmail "your-email@example.org" -GenreBatchSize 12
```

Выход `data/raw/book_genres.csv`: `isbn,genre,source_url`. Дополнительные локальные результаты `book_genres.attempts.json`, `book_genres.coverage.json` фиксируют уже обработанные ISBN, долю покрытия, пропуски и ошибки; кэш JSON сохраняется в `data/raw/openlibrary_cache/`. Ни файл с взаимодействиями, ни жанровые файлы не добавляются в Git.

**Принцип воспроизводимости:** после добавления жанров необходимо целиком заново построить KG, переобучить эмбеддинги и переоценить модель. Используйте отдельный **явный** флаг, чтобы случайно не изменить исходный эксперимент:

```powershell

powershell -ExecutionPolicy Bypass -File .\scripts\run_vkr_windows.ps1 -Mode app -SkipInstall
```

Параметр `-UseGenres` действует также на `main`, `study-quick`, `study-full` и `compare-quick/full` (он осознанно меняет обучающий граф). **Сравнивать с опубликованными 42 опытами можно только в отдельном новом протоколе и при описании изменения графа**.

Отчёты `vkr_preparation_report.json` и `vkr_graph_audit.json` показывают `genre_fact_edges`, `genre_books_covered`, `genre_book_coverage` и наличие HTTPS-происхождения. Небольшое ненулевое покрытие **не закрывает полностью** требование ТЗ о жанрах.

## 2. Визуализация эмбеддингов в Streamlit

Файл `src/vkr_embedding_projection.py` вычисляет PCA непосредственно из актуальных `results/embeddings/vkr_n2v.npy` и `vkr_n2v_ids.json`. В `src/vkr_app.py` добавлена пятая вкладка **«Пространство эмбеддингов (PCA)»**.

- На интерактивной диаграмме разными цветами отображаются `book`, `user`, `author`, `publisher` и при наличии `genre`; всплывающая подсказка показывает ID и подпись.
- Исходная книга и рекомендованные книги выделяются и **не исключаются** случайной подвыборкой.
- Размер визуализируемой подвыборки ограничен (100–1500), выбор детерминирован при `seed=42`.
- Выводится объяснённая дисперсия первых двух компонент. Это **не оценка точности рекомендаций** и не схема существующих связей графа: реальные связи демонстрируются во вкладке доказательных путей.

В исходном ТЗ/плане допускались `t-SNE / UMAP / PCA`; PCA реализована без новых необязательных тяжёлых библиотек. Картинки прошлой курсовой в этой вкладке не используются. Проверка ручного отображения на Windows и скриншоты для отчёта пока остаются за исполнителем локального прогона.

## 3. Первый эксперимент faithfulness: удаление доказательных рёбер и переобучение

Новый модуль `src/vkr_faithfulness.py` выполняет **не косметическое скрытие объяснения**, а изменение **подтверждённых исходных рёбер** выбранного пути.

1. Загружает оригинальный train-only KG и обученные Node2Vec-эмбеддинги через `vkr_dashboard` с контролем SHA-256.
2. Выбирает исходную книгу и до двух рекомендаций, для которых есть допустимые фактические пути длиной 2.
3. Повторно обучает Node2Vec на **неизменённом графе** с теми же параметрами и seed (контроль воспроизведения).
4. Для каждого объяснения удаляет **точно** соответствующие рёбра с совпадающим `relation` и provenance, не затрагивая train/test-файлы.
5. Повторно обучает Node2Vec с фиксированным seed и сравнивает cosine score и позицию рекомендованной книги в зафиксированном каталоге.
6. Повторяет процедуру с контрольным удалением **такого же количества рёбер тех же отношений**, но не затрагивающих узлы объясняющего пути; сравнивает изменение score с контрольным.
7. Сохраняет `results/faithfulness/faithfulness_pairs.csv` и `faithfulness_report.json` локально. Если после удаления исчезает эмбеддинг, это явно отмечается как недоступность, а не подменяется нулевой оценкой.

Запуск из корня репозитория **после `quick` или `main`**, с обновлённым скриптом:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_vkr_windows.ps1 -Mode faithfulness -SkipInstall
```

Для задания исходной книги, изменения числа объектов и контроля:

```powershell
.\.venv-vkr\Scripts\python.exe -m src.vkr_faithfulness --source-book "book:0002251760" --max-pairs 2 --controls 2 --method shortest
```

**Научное ограничение:** даже после переобучения score меняется не только из-за прямого влияния удалённой связи, но и из-за перестройки случайных блужданий и пространства эмбеддингов. Наши контроли сопоставлены по **типам и количеству** связей, **но пока не по степеням и положению узлов**. Это предварительная проверка чувствительности объяснений, **не доказательство причинности**. Для итоговой ВКР нужны несколько seed и независимых разбиений, достаточное число пар, degree-matched controls, анализ доверительных интервалов, сравнение способов объяснений, ранжирования и задержки.

**Никаких реальных результатов faithfulness пока не публикуется**: код прошёл только автоматический синтетический тест. Если выбранная книга не имеет пути длиной 2, программа сообщает `no_explainable_pairs` без выдуманных чисел.

## 4. Отдельное исследование shortest/informative и posthoc/rerank

В `src/vkr_explanation_study.py` добавлен эксперимент **именно для поиска/ранжирования похожих книг**: книга-кандидат получает максимальный косинус Node2Vec к одной из трёх понравившихся пользователю train-книг, а релевантность вычисляется по положительным предпочтениям, отложенным ещё **до** построения графа.

Протокол сохраняет единый каталог кандидатов, исключает все ранее оценённые в train книги и сравнивает 8 вариантов на **одной validation-подвыборке**: `shortest` / `informative`, `posthoc` / `rerank` и `alpha ∈ {0.2, 0.5, 0.8}`. Он отдельно фиксирует P/R/F1/NDCG/MRR при k=5,10,20, процент рекомендаций с допустимым объяснением, среднюю длину пути, частоту усечения поиска и время.

Для этого используется **новый split seed=2042**, не тот, на котором отбирались модели в этапе эмбеддингов. Модель Node2Vec фиксирована заранее по первой сравнительной серии; она не перенастраивается по test объяснений. **На test вычисляется только победившая на validation конфигурация и заранее установленный контроль posthoc**. Тестовый набор не участвует в выборе method/alpha.

Команда для Windows (реальный Book-Crossing должен быть в `data/raw/`):

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_vkr_windows.ps1 -Mode explanations -SkipInstall
```

Результаты: `results/explanation_study/explanation_validation_grid.csv` (8 проверенных настроек на validation), `explanation_study_report.json` (выбранная настройка и test), `train_only_node2vec/` (векторы). Все артефакты локальные, в Git не попадают. По умолчанию исследуются 20 пользователей из набора с test-положительными метками, единый candidate pool 25 и пути длиной 2; для исследования более длинных путей есть CLI `--max-depth 4` с ограниченным поиском.

**Ограничения:** это только preference proxy на отложенных оценках, **не оценка экспертной семантической похожести книг**. При 20 пользователях и ограниченном пуле статистическая значимость неизвестна. Время поиска зависит от процессора, а при `truncated=true` лучшие пути полного графа могут быть не найдены. **Числа реального запуска пока отсутствуют**; CI проверяет модуль только синтетически. Нельзя подставлять значения от старой курсовой.

## 5. План дальнейшей программы

После локальной проверки новых режимов на реальном Book-Crossing:

- Выполнить и сохранить жанровый пилот и долю покрытия; определить подходящий легальный массовый источник с воспроизводимой версией и ручной верификацией выборки.
- Выполнить пару faithfulness-опытов с фиксацией удалённых фактов, времени обучения, score/rank и контрольных удалений; **не присваивать результатам заранее ожидаемое направление**.
- Провести независимую количественную серию для `shortest` и `informative` и для `posthoc`/`rerank` при нескольких `alpha`: NDCG@k, coverage, длина/тип пути, информативность и время.
- Подготовить актуальные скриншоты из Streamlit и схематические иллюстрации в отчёте с нормативными ссылками на рисунки и таблицы.
- Позднее — небольшой протокол пользовательской оценки понятности/полезности объяснений; **не заполнять ответы за участников**.

## Проверки и ограничения передачи

Синтетические тесты проверяют точность удаления фактов, отсутствие подмены происхождения, детерминированность PCA, безопасное ISBN-сопоставление и сохранение исследовательских артефактов. Исторические исследования и результаты сравнительной серии находятся в отдельных папках. Все новые факты и файлы с пользовательскими ID остаются вне публичного Git. Успешные тесты не заменяют выполнения новых исследований на реальных данных.

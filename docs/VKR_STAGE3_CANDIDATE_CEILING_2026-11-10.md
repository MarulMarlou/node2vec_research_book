# Этап 3 ВКР — выявление ограничения начального отбора книг (candidate ceiling)

**Дата проверки:** 10 ноября 2026 года.
**Источник:** три предоставленных пользователем файла реального эксперимента \`explanation_study_report(5).json\`, \`explanation_validation_grid(5).csv\`, \`explanation_test_paired_deltas(1).csv\`. Числовая проверка проведена независимым чтением CSV/JSON; сами файлы индивидуальных результатов и исходные рейтинги не публикуются в GitHub. CI не заявляется как повторное обучение на реальном Book-Crossing.

## 1. Главный результат: первичный отбор теряет большинство подходящих книг

Эксперимент на независимом разбиении \`split_seed=2092\`, **120 тестовых пользователей из 131 подходящего**, train=5120, validation=560, test=727 взаимодействий; train-only граф **1726 вершин, 7120 рёбер**. Модель Node2Vec: dim=64, walk_length=20, num_walks=4, epochs=3, p=q=1, window=3, model seed=43; candidate_pool=25; длина объяснения ≤4; max_paths=200, max_expansions=5000. Входные CSV Book-Crossing имеют ранее зафиксированные SHA-256. Жанров **нет** (\`genre_csv=null\`).

Кандидаты ранжируются по максимальному косинусному сходству с **не более тремя ранее положительно оценёнными книгами** пользователя (только train, threshold≥7). Исходный pool состоит из первых 25, все дальнейшие методы объяснения/переранжирования могут переставлять **только эти 25 книг**.

| Диагностика на test | Весь модельный каталог | Top-100 базового cosine | Top-25 базового cosine |
|---|---:|---:|---:|
| Пользователи с хотя бы одной test-положительной книгой | **120/120 (100%)** | **77/120 (64,17%)** | **39/120 (32,5%)** |
| Средняя доля восстановленных удержанных позитивов | **1,0000** | **0,24275** | **0,08663** |

Критическая причинно-техническая граница: **81/120 тестовых пользователей (67,5%) не имеют ни одной положительной test-книги среди 25 кандидатов**. Это делает невозможным её продвижение в top-10 при любом rerank на данном пуле — независимое от α и метода объяснений ограничение. У **98/120 (81,67%) NDCG@10 был равен нулю одновременно у posthoc и rerank**, из них 81 не имели позитивов в исходном пуле и оставшиеся **17** имели позитивного кандидата, но ни один из двух методов не поднял его в top-10. Лишь у **22/120** было хотя бы одно релевантное попадание в top-10 у любого из двух методов. Последняя декомпозиция следует из агрегированных потолков и индивидуальных top-10 метрик, без раскрытия пользовательских ID.

**Важное ограничение:** 120/120 \`catalog_has_positive_users\` не доказывает отсутствие cold-start в эксплуатации: holdout после ограничения строится только из пользователей и книг обучающего подграфа. Набор до 150 пользователей / 1000 книг — ограниченная учебная выборка, а не полный Book-Crossing. Показатель «доля пользователей с хотя бы одним попаданием» **не равен** среднему Recall; обе величины приводятся отдельно. Доля из test-позитивов в top-100 — лишь **верхняя граница** recall ранжирования, если увеличить candidate pool до 100; непосредственно rerank на 100 ещё **не запускался**.

## 2. Validation: какой метод выбрали до test

Восемь настроек постобработки *одной обученной Node2Vec*, 120 validation пользователей из 127. По заранее заданному максимуму validation NDCG@10=**0,042646** выбрана конфигурация **\`informative + rerank, alpha=0,5\`**. Краткая сводка:

| Метод/режим | alpha | Validation NDCG@10 | Валидационная доля усечений |
|---|---:|---:|---:|
| shortest / posthoc | 0 | 0,040799 | 0% |
| informative / posthoc | 0 | 0,040799 | 0% |
| shortest / rerank | 0,2 | 0,042043 | 0% |
| shortest / rerank | 0,5 | 0,041034 | 0% |
| shortest / rerank | 0,8 | 0,040810 | 0% |
| informative / rerank | 0,2 | 0,041616 | 0% |
| **informative / rerank** | **0,5** | **0,042646** | **0%** |
| informative / rerank | 0,8 | 0,042253 | 0% |

В отличие от ранних неоптимизированных опытов, все оценённые поиски informative на top-10 завершились без усечения. Для informative постобработки средняя длина пути составила ~3,16 ребра против ~2,16 у shortest; время 5,182 мс против 1,105 мс на кандидат, то есть приблизительно в 4,69 раза больше. Качество одного posthoc не зависит от типа найденного объяснения, поскольку порядок книг неизменен.

## 3. Test и парный bootstrap на 120 пользователях

Использована *одна заранее выбранная на validation* конфигурация и предопределённый posthoc-контроль того же informative метода.

| Метрика | Informative/posthoc | **Informative/rerank α=0,5** | Средняя разница (rerank−posthoc) |
|---|---:|---:|---:|
| P@5 | 0,02667 | **0,03000** | +0,00333 |
| P@10 | 0,02250 | **0,02333** | +0,00083 |
| NDCG@10 | **0,035940** | 0,033244 | **−0,002696 (−7,50% относ.)** |
| MRR@10 | **0,062566** | 0,052857 | −0,009709 |
| NDCG@20 | **0,050140** | 0,044428 | −0,005711 |
| Покрытие top-10 объяснениями | 100% | 100% | 0 |

Парный user bootstrap: **3000** повторов, \`seed=2395\`, 95%-е процентильные интервалы (условны на фиксированную модель, split и когорту):

| Разность | 95%-й доверительный интервал | Пользователей лучше / хуже / без изменения |
|---|---|---|
| ΔNDCG@10 | **[−0,012169; +0,006302]** | **11 / 8 / 101** |
| ΔP@10 | [−0,004167; +0,005833] | 5 / 4 / 111 |
| ΔMRR@10 | [−0,032366; +0,010517] | 10 / 8 / 102 |
| ΔCoverage | [0; 0] | 0 / 0 / 120 |

**Вывод:** выбранный на validation informative-rerank на данном test имеет среднее NDCG@10 **ниже** posthoc. CI включает ноль; нельзя утверждать подтверждённую статистически деградацию или превосходство. Улучшение у 11 пользователей, ухудшение у 8, **101 — без изменения**. Этот результат нельзя скрывать или заменять более благоприятным split=2052/2072: он показывает нестабильность показателей на ограниченных выборках.

## 4. Проверка согласованности данных

- В \`explanation_validation_grid(5).csv\` **8 уникальных конфигураций по 27 колонкам**. Все показатели совпадают с \`validation.results\` в JSON до округления float.
- В \`explanation_test_paired_deltas(1).csv\` **120 строк × 13 колонок**, индексы 0..119, исходные \`User-ID\` отсутствуют, пропусков/несконечных чисел нет.
- Для каждого пользователя точно воспроизведено \`rerank−posthoc\` по NDCG@10, P@10, MRR@10 и coverage; все средние совпадают с JSON.
- Повторно созданы 3000 bootstrap-индексов с \`numpy.default_rng(2395)\`; все четыре интервала воспроизведены без расхождения.
- Источники пользовательской релевантности — положительные (rating≥7) **held-out рейтинги**. Это proxy предпочтений, а не экспертный gold-standard семантического сходства. Test-метки не участвовали в выборе α, методе объяснения, генерации candidate pool или обучении графа.

## 5. Следующие научные действия

1. **Сравнить одинаковую train/validation/test и модель при pool=25 vs pool=100**, а не разницу между разными split. Для каждого пула отдельно выбрать конфигурацию по validation и оценить test только после выбора. Помимо сравнения двух самостоятельно выбранных pipeline следует оценить pure pool-size effect **при фиксированном методе/alpha**. Сохранять индивидуальные анонимизированные парные разности и bootstrap-ограничения.
2. Разработать улучшенный candidate generator (например, смесь cosine по нескольким seed-книгам, train-popularity, neighborhood signals) и сравнить с базовым top-25 при **фиксированном ограничении до 25 кандидатов**; влияние параметров выбирать на validation и тестировать на новом split. Не выдавать эффект увеличения пула за улучшение метрики качества генератора.
3. Проверить качество на более широкой выборке и нескольких model/split seeds; зафиксировать uncertainty и затраты времени.
4. **Вернуться к незакрытому этапу 1:** жанровое обогащение Book-Crossing с проверяемым provenance и отдельное сравнение «с жанрами/без» на одинаковом split.

Все исходные CSV, сырые пользовательские ID и результаты нового локального эксперимента остаются вне git; публикуется только проверенная научная сводка. Исследования полного каталога и жанров пока не выполнены.

## Этап 1: подготовка данных и граф знаний

Выполнено:

- Загружены реальный `BX-Books.csv` (271 379 исходных строк) и `BX-Book-Ratings.csv` (1 149 780 строк). Чтение semicolon/latin-1, поддержка экранированных кавычек.
- После нормализации: 271 378 уникальных ISBN. Из 433 671 явных оценок (1–10) с известными ISBN сопоставлены 383 853. Нулевые оценки — неявные сигналы, они отдельно исключены, а не трактуются как отрицательные.
- До построения графа выполнено детерминированное train/test разбиение. Для основного ограниченного эксперимента оставлено 37 432 train-оценки и 5 920 test-оценок.
- Построен ориентированный типизированный `MultiDiGraph`: книга, читатель, автор, издательство; отношения `rated`, `written_by`, `published_by`; исходный файл и номер записи для каждого ребра. Отдельно сохранена неориентированная проекция для Node2Vec.
- Реальная структура: 8 130 узлов (5 000 книг, 990 пользователей, 1 709 авторов, 431 издательство), 47 432 ребра. Компонент слабой связности — одна (все 8 130 узлов); изолированных узлов нет; медианная степень 7, 90-й процентиль 25, максимальная 1 511.
- `src/vkr_graph_audit.py` проверяет связность, степени, наличие источников, совпадение рёбер с train и отсутствие утечки test в граф. Для зафиксированной реальной модели проверка пройдена.

**Незакрытое требование этапа:** жанры из внешнего достоверного источника пока не добавлены. Book-Crossing не содержит исходного столбца жанра; нельзя изобретать их. Импорт с обязательной ссылкой `source_url` реализован, само обогащение ещё требуется.

## Этап 2: векторные представления

Уже выполнено:

- Реализован Node2Vec: взвешенные случайные блуждания второго порядка с p/q, однопоточный Word2Vec Skip-gram и стабильные seed/hash; сохранение эмбеддингов вместе с ID вершин.
- Проведён основной smoke-прогон на реальных 5 000 книгах: dim=64, walk_length=20, num_walks=4, epochs=3, p=q=1, seed=42; обучение ~10,38 с в контрольной среде, полный цикл ~41,91 с.
- Раздельно рассчитаны метрики user→book (P@10=0,0245; NDCG@10=0,0396) и book→book preference proxy. В последнем Node2Vec NDCG@10=0,0262, метаданный Jaccard NDCG@10=0,0303. Это **результаты одной конфигурации**, не окончательное сравнение.
- `src/vkr_embedding_study.py` выделяет train/validation/test и подбирает параметры только на validation; тестовая часть используется один раз, после выбора. Быстрый режим — 3 конфигурации, расширенная сетка — 12 конфигураций × 3 seed = 36 Node2Vec-запусков.
- Пилотный **новый** опыт с отдельным split seed=2027 и 150 пользователями / 1 000 книг: train 5 166, validation 556, test 693; 3 варианта p/q. Лучший по validation NDCG@10 — p=q=1 (0,009406); его test NDCG@10=0,015765. Это лишь пилот, данные другого разбиения нельзя объединять с предыдущим smoke-прогоном.
- Контрольный Jaccard в этом опыте достигает validation NDCG@10=0,063423, но не является методом эмбеддингов.

**Осталось до сдачи второго этапа:** интегрировать и проверить TransE (триплеты, модель, сопоставимый протокол оценки), провести не менее 30 документированных *сравнительных* опытов, проанализировать гиперпараметры/время и подготовить таблицы и графики. До этого этап не обозначаем завершённым.

## Локальный запуск Windows 11 / PowerShell / PyCharm

1. Установить Python 3.11 и Git. Использовать **ветку** `feature/vkr-stage1-typed-graph-holdout`, а не `main`. Неподтверждённые локальные изменения предварительно сохранить/закоммитить.
2. Создать `data/raw` в корне проекта и положить туда **точно** `BX-Books.csv` и `BX-Book-Ratings.csv` (без изменения имён).
3. В PowerShell, открытом в корне проекта, выполнить:

```powershell
git fetch origin
git switch --track origin/feature/vkr-stage1-typed-graph-holdout
powershell -ExecutionPolicy Bypass -File .\scripts\run_vkr_windows.ps1 -Mode quick
powershell -ExecutionPolicy Bypass -File .\scripts\run_vkr_windows.ps1 -Mode app -SkipInstall
```

Для повторного запуска на полном исследовательском подграфе: `powershell -ExecutionPolicy Bypass -File .\scripts\run_vkr_windows.ps1 -Mode main -SkipInstall`. Для тестов: `-Mode tests`. Если ветка уже существует, `git switch feature/vkr-stage1-typed-graph-holdout` вместо `git switch --track ...`.

**Важно:** режимы quick и main записывают в один каталог результатов. Каждый следующий запуск обновляет файлы; важные предыдущие отчёты перед запуском следует архивировать в отдельный каталог. Измерения по времени на компьютере пользователя будут отличаться.

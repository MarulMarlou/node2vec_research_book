# ВКР: проверка оптимизированного informative-поиска, эксперимент split=2072

**Дата фиксации:** 10 ноября 2026 года.  
**Исходные материалы:** предоставленные исполнителем \`explanation_study_report(3).json\` и \`explanation_validation_grid(3).csv\`. Исходные измерения выполнены локально на Book-Crossing; **GitHub Actions не повторяет эксперимент на реальных CSV**.

## Краткое заключение

**Оптимизация поиска четырёхрёберных объяснений устранила прежнее 100%-ное усечение informative-поиска на новом validation-прогоне**: для всех восьми вариантов \`truncated_fraction=0\`. На том же validation конфигурация \`shortest + rerank α=0,2\` выбрана по максимальному NDCG@10=**0,073146**; на test NDCG@10 выбранной конфигурации составил **0,066130** против **0,062838** у заранее установленного контроля shortest/posthoc (+0,003292, **+5,24% относ.**). Улучшение не является статистически подтверждённым и не доказывает причинность графовых объяснений.

## 1. Проверенные условия эксперимента

| Параметр | Значение |
|---|---|
| Отдельное разбиение данных | \`seed_split=2072\`; train=5 181, validation=517, test=690 взаимодействий |
| Обучающий train-only KG | 1 735 узлов, 7 181 рёбер |
| Модель Node2Vec | \`dimensions=64, walk_length=20, num_walks=4, epochs=3, p=q=1, window=3, seed=43\` |
| Пользователи | 40 на validation из 128 eligible; 40 на test из 134 eligible |
| Пул предварительно отобранных кандидатов | 25 книг на пользователя |
| Максимальная длина пути | 4 ребра |
| Лимиты поиска | \`max_paths=200\`, \`max_expansions=5000\` |
| Жанровые данные | **Нет** (\`genre_csv=null\`) |
| Проверка источника | SHA-256 исходных CSV совпадает с предыдущими протоколами 42 экспериментов |

На validation рассмотрены **восемь настроек постобработки одной Node2Vec-модели**, а не восемь новых обучений Node2Vec. Модель и каталог общие; методы объяснений \`shortest\` и \`informative\`, режимы \`posthoc\` и \`rerank\`, коэффициенты α ∈ {0,2; 0,5; 0,8}. Отбор выполнен на **validation**, test использован только для выбранной настройки и заранее предусмотренного контроля.

| shortest | rerank | 0,5 | 0,054102 | 0,0250 | 100% | 0% | 2,275 | 1,602 |

| informative | rerank | 0,8 | 0,061404 | 0,0275 | 100% | 0% | 3,150 | 4,967 |

В старом эксперименте \`split=2062\` у informative было **100% усечений на validation top-10** даже после увеличения лимитов до 200/5000; новая реализация (\`split=2072\`) даёт **0% на новой validation-когорте**. Это убедительная проверка корректности нового подхода на конкретных данных, **но не измерение ускорения между двумя реализациями на одинаковом графе**. Для прямого сравнения времени старой DFS и новой typed-join версии требуется отдельный benchmark на одинаковых исходных парах и среде.

Среднее время informative/posthoc **5,656 мс**, shortest/posthoc **1,114 мс**, отношение ~5,08. Informative теперь выбирает более длинные пути (3,195 против 2,130 ребра) без усечения, но не выигрывает по NDCG@10 при том же α=0,2.

| Метрика | Shortest/posthoc | **Shortest/rerank α=0,2** |

| MRR@10 | 0,098750 | **0,105833** |

| Покрытие top-10 | **100%** | **100%** |

| Длина подтверждённого пути | 2,125 | 2,215 |

Относительное преимущество rerank по test NDCG@10 = **+5,24%** (абсолютное +0,003292). Это локальный эффект для **40 отобранных пользователей** одного test split: на новые разбиения, модели и полную совокупность пользователей автоматически не переносится. **Тестового сравнения informative vs shortest нет:** informative не был выбран по validation, поэтому метод не прогонялся на test. Нельзя на основании нулевого усечения на validation утверждать нулевое усечение informative на всей генеральной совокупности или всех test-пользователях.

## 4. Перекрёстная проверка и ограничения

- Проверены **все 8 строк** CSV и соответствующие элементы JSON: численные значения согласованы (с точностью стандартного округления/записи float), пропусков в 27 колонках CSV нет.
- \`selected\` совпадает с максимальным validation NDCG@10; \`test_best_rerank\` совпадает с \`test_selected\`, потому что победитель сам является reranker.
- Идентичность \`shortest/posthoc\` и \`informative/posthoc\` по качеству объясняется отсутствием rerank; сами найденные пути существенно различаются по длине.
- Жанры не подключены; пользовательские оценки используются как proxy релевантности, а не независимая экспертная семантическая разметка.
- Без индивидуальных (per-user) метрик нельзя построить корректный **парный bootstrap** разницы NDCG между двумя вариантами на test. Два агрегированных средних не позволяют восстановить дисперсию разности.
- Лимиты 200/5000, размер пула 25 и 40 выбранных пользователей ограничивают переносимость выводов. Нулевая усечённость в этом эксперименте не гарантирует отсутствия усечений на полном Book-Crossing.

## 5. Следующий протокол: условные парные доверительные интервалы

**После** проверки файлов в код \`src/vkr_explanation_study.py\` добавлены:
- хранение персонифицированных парных test-метрик **только внутри функции**, а в выходном CSV — **анонимный порядковый номер пользователя**, метрики выбранного на validation rerank и posthoc и их разницы;
- парный user-level bootstrap (3 000 повторных выборок) с 95%-ным процентильным интервалом для ΔNDCG@10, ΔP@10, ΔMRR@10 и Δ покрытия;
- сохранение \`explanation_test_paired_deltas.csv\` и поля \`paired_rerank_vs_posthoc\` в JSON; **все IDs пользователей из выходных файлов исключены**.

Интервал будет **условным относительно одного фиксированного split, model seed и выбранной когорты пользователей**. Он **не** учитывает изменчивость модели/параметров, другие разбиения и селективную репрезентативность 40 пользователей. Нельзя выдавать его за универсальную статистическую значимость.

**В предоставленном JSON \`split=2072\` этого поля ещё нет.** Интервалы и индивидуальные эффекты для текущего пилота не придуманы и задним числом не рассчитаны. Для следующего отчёта требуется новый запуск с отдельным split и обновлённым кодом.

**Статус:** технический долг по 100%-му усечению informative на проверенной выборке закрыт; для завершения полного научного исследования нужны парные интервалы, повторные splits, дополнительная проверка статистики и обогащение графа жанрами по проверяемым источникам.

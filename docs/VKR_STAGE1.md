**Статус на 14.10.2026:** граф знаний построен и проверен на реальном Book-Crossing, включая локальный запуск на Windows. **Обогащение подтверждёнными жанрами ещё не завершено**, поэтому полный набор сущностей из ТЗ пока не собран.

[Главная страница](../README.md) · [Windows-инструкция](VKR_WINDOWS.md) · [План сдачи](VKR_MILESTONES_1_2.md)

## Источник и очистка

Источник: [Book-Crossing / GroupLens](https://grouplens.org/datasets/book-crossing/), исходные `BX-Books.csv` и `BX-Book-Ratings.csv` в `data/raw/`. Формат — `latin-1`, `;`, экранированные кавычки. Скан исходных записей показал, что необходимо учитывать `escapechar='\\'`; 19 ранее пропускавшихся строк книг теперь обрабатываются.

Первичные характеристики полученного набора (полные, **до** ограничения исследовательской выборки):

| Сущность | Наблюдение |
|---|---:|
| Исходные строки `BX-Books.csv` | 271 379 |
| Уникальные ISBN после нормализации | 271 378 |
| Все строки оценок | 1 149 780 |
| Оценки `0` — неявные взаимодействия | 716 109 |
| Оценки `1…10` — явные | 433 671 |
| Явные оценки с ISBN из таблицы книг | 383 853 |

Оценка `0` **не считается отрицательной**. Положительная оценка для итоговых метрик — `rating >= 7`.

## Разделение и предотвращение утечки

1. Сначала читаем исходные CSV и нормализуем идентификаторы.
2. Делим явные оценки на **train/test до построения графа**; для каждого пользователя с несколькими положительными оценками часть откладывается в test, сохраняя положительное обучение.
3. Выбор популярных пользователей/книг проводится только по `train`, не по отложенным меткам.
4. `test` остаётся для оценки, его `rated`-рёбра **не включаются** в обучающий граф.
5. `src/vkr_graph_audit.py` проверяет пересечения train/test, точное совпадение рёбер `rated` с train, наличие файлов происхождения и общую структуру графа. Отчёт сохраняется в `results/metrics/vkr_graph_audit.json`.

В отдельном сценарии исследования эмбеддингов `src/vkr_embedding_study.py` используется **train/validation/test** с выбором гиперпараметров только по validation. Это **другой split**, и его метрики нельзя смешивать с основным train/test.

## Схема типизированного графа

Граф: `networkx.MultiDiGraph`, ориентированные типизированные рёбра.

| Тип вершины | ID | Роль |
|---|---|---|
| Книга | `book:<ISBN>` | Объект рекомендации |
| Пользователь | `user:<User-ID>` | Обучающие явные рейтинги |
| Автор | `author:<ключ>` | Из метаданных книги |
| Издательство | `publisher:<ключ>` | Из метаданных книги |
| Жанр | `genre:<ключ>` | Поддерживается схемой, **в реальном основном графе пока отсутствует** |

| Рёбра | Направление | Основание |
|---|---|---|
| `rated` | пользователь → книга | Только оценка в train |
| `written_by` | книга → автор | Поле автора Book-Crossing |
| `published_by` | книга → издательство | Поле издательства Book-Crossing |
| `has_genre` | книга → жанр | Только предоставленные проверяемые внешние жанры |

Поля ребра содержат происхождение: `source_file`, `source_row`, при наличии — `source_url`. `source_row` — порядковый номер разобранной записи, не обязательно физический номер строки файла при сложном цитировании. Для Node2Vec создаётся отдельная неориентированная проекция; она **не заменяет** типизированный граф при объяснениях.

## Воспроизведение

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_vkr_windows.ps1 -Mode quick
```

После выполнения будут созданы:

- `data/processed/vkr_train_ratings.csv`, `vkr_test_ratings.csv`;
- `data/processed/vkr_knowledge_graph.graphml` — исходный KG;
- `data/processed/vkr_node2vec_graph.graphml` — проекция;
- `data/processed/vkr_preparation_report.json` — исходные параметры;
- `results/metrics/vkr_graph_audit.json` — проверка структуры и утечек.

Отдельно без обучения: `python -m src.vkr_prepare`, затем `python -m src.vkr_graph_audit` (из окружения Python 3.11).

## Что ещё необходимо для закрытия этапа

**Жанровое обогащение:** Book-Crossing не имеет поля жанра. В `src/vkr_prepare.py` предусмотрен импорт `isbn,genre,source_url`; ссылку на источник необходимо указывать и проверять. Не следует выводить жанры из названий книг и считать их подтверждёнными фактами. Автоматический сбор/сопоставление ISBN с Open Library/Wikidata и исследование покрытия жанров ещё не выполнены.

Также для отчётной сдачи требуются описание качества исходных данных, схема сущностей/отношений, объяснение ограничений выборки и таблицы результата аудита. Не передавайте исходные CSV с пользовательскими взаимодействиями как публичный исходный код.

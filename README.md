# Рекомендательная система книг на основе графа знаний

**Исследовательский прототип ВКР — промежуточная сдача этапов подготовки графа и исследования эмбеддингов.**

Реализована подготовка данных, построение типизированного графа знаний и обучение эмбеддингов **Node2Vec**. Дополнительно доступна демонстрация рекомендаций похожих книг с графовыми объяснениями в Streamlit.

## Быстрый запуск на Windows

Требуются **Python 3.11**, Git, исходные `BX-Books.csv` и `BX-Book-Ratings.csv`. Python 3.15 не используется: зависимости зафиксированы и проверены на 3.11.

Если вы ещё не склонировали репозиторий:

```powershell
git clone --branch feature/vkr-stage1-typed-graph-holdout --single-branch https://github.com/MarulMarlou/node2vec_research_book.git
cd node2vec_research_book
```

Поместите файлы в `data/raw/BX-Books.csv` и `data/raw/BX-Book-Ratings.csv`. Исходные пользовательские рейтинги **не включены в Git**. Источник и описание набора — [GroupLens, Book-Crossing](https://grouplens.org/datasets/book-crossing/). Перед использованием проверьте условия распространения оригинального набора.

```powershell
py -3.11 --version
powershell -ExecutionPolicy Bypass -File .\scripts\run_vkr_windows.ps1 -Mode quick
powershell -ExecutionPolicy Bypass -File .\scripts\run_vkr_windows.ps1 -Mode app -SkipInstall
```

После запуска Streamlit откройте **http://localhost:8501**. Не закрывайте терминал с работающим сервером.

Режимы запуска:

| Режим | Назначение | Примечание |
|---|---|---|
| `quick` | Построение небольшого графа, обучение, метрики, аудит | До 150 пользователей, 1 000 книг |
| `main` | Основной исследовательский подграф | До 1 000 пользователей, 5 000 книг |
| `tests` | Автоматические тесты нового контура ВКР | Нужны установленные зависимости |
| `app` | Интерфейс рекомендаций | Сначала выполните `quick` или `main` |

**Эксперимент с выделенной validation-выборкой** запускается отдельно (не переписывает артефакты основного интерфейса):

```powershell
.\.venv-vkr\Scripts\python.exe -m src.vkr_embedding_study --mode quick --max-users 150 --max-books 1000
```

Расширенная сетка `--mode full` содержит 12 конфигураций Node2Vec × 3 фиксированных seed (36 запусков) и может быть ресурсоёмкой. **Это не сравнение с TransE.**

После запуска исправлен порядок формирования окончательного train-only каталога, добавлен popularity baseline и контроль mean/std. **Присланный старый отчёт не используем как итоговые 42 эксперимента**. ### Новое: контролируемое сравнение Node2Vec и TransE (этап стажировки)

Отдельный сценарий `src/vkr_compare_embeddings.py` обучает **оба алгоритма** на едином train-only типизированном графе, выбирает конфигурацию каждого по validation и использует test только после выбора. В отличие от прежних прогонов, в нём отдельно откладываются реально наблюдавшиеся низкие оценки (1–6), что позволяет считать ROC-AUC на явно размеченных положительных/низких рейтингах, **не называя все неизвестные пары отрицательными**.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_vkr_windows.ps1 -Mode compare-quick -SkipInstall
```

Результаты относятся к ограниченному подграфу (до 150 пользователей, 1000 книг), не являются доказательством статистически значимого превосходства. [Итоговый отчёт, все таблицы и ограничения](docs/VKR_STAGE2_FULL_RESULTS_2026-11-10.md). Результаты текущего `compare-full` сохраняются в `results/comparison/`, отдельно от интерфейса.

## Парный bootstrap и обнаруженный узкий участок отбора книг (10.11.2026)

На реальном **split=2082** проверены 8 конфигураций объяснений, **80 validation и 80 test пользователей**. Выбранный на validation `shortest + rerank α=0,5` показал на test NDCG@10 **0,032821** против **0,028946** у posthoc (+13,39% относ.). **Но 95%-й парный bootstrap-интервал ΔNDCG@10 [−0,001410; +0,009562] включает ноль**: статистически подтверждённого улучшения основной метрики пока нет. Лишь **7 пользователей улучшились, 4 ухудшились, 69 не изменились**; **66/80 не имели релевантного попадания в top-10 ни у одной модели**. [Проверенный научный разбор](docs/VKR_STAGE3_PAIRED_BOOTSTRAP_2026-11-10.md).

**Следующая задача — не очередной подбор α, а исследование candidate-recall ceiling.** В код добавлена раздельная диагностика: наличие позитивов в каталоге модели, среди первых 25 и 100 базовых cosine-кандидатов и в фактически переданном rerank пуле. Новый независимый `split=2092`, до 120 пользователей, без изменения выбора модели по validation:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_vkr_windows.ps1 -Mode explanations-ceiling -SkipInstall
```

Артефакты сохраняются в `results/explanation_study_ceiling/` (вне Git). **Этот новый опыт ещё не выполнен на реальных данных**. Ограничения жанрового обогащения и итоговой пользовательской оценки остаются.

## Третий проверенный пилот и исправление информативного поиска (10.11.2026)

**Реальные данные, split=2062:** 40 test-пользователей, обучение на 5 203 взаимодействиях. На validation выбран `shortest + posthoc` (NDCG@10=0,036019). На test posthoc NDCG@10=0,053755; отдельно предопределённый для сравнения rerank α=0,2 дал NDCG@10=0,057442 (+6,86% относительно posthoc), но не был validation-победителем. Несмотря на увеличение бюджета до **200 путей/5000 расширений**, `informative` оставался **усечённым для 100% top-10 запросов**. Faithfulness: **4 рекомендованные пары × 20 контрольных удалений**; во всех четырёх случаях падение cosine больше среднего контроля, но не подтверждена статистическая значимость. [Подробный проверенный отчёт](docs/VKR_STAGE3_SEARCH_BUDGET_AND_EXTENDED_FAITHFULNESS_2026-11-10.md).

**Исправлено в коде:** прежний взрывной DFS для четырёхрёберного объяснения заменён структурным поиском через общие промежуточные книги и ранжирование пар признаков по потенциальной информативности. Тесты сравнивают его с исчерпывающим поиском на малом графе. **Новых реальных измерений после исправления ещё нет** — для них выделен свежий split=2072 и режим `explanations-optimized`:


## Результаты второго исследования объяснений (10.11.2026)

Получен и проверен новый реальный эксперимент **`max_depth=4`, split seed=2052, 40 тестовых пользователей**. На validation выбрано `shortest + rerank α=0,5`; на test NDCG@10 **0,077620** против **0,067643** у фиксированного `shortest + posthoc` (относительная разница +14,75%), покрытие объяснениями top-10 **100% против 94,25%**. При этом NDCG@20 чуть ниже у rerank, а поиск `informative` усекался в **100%** случаев и требует отдельной проверки с увеличенным бюджетом. Повторный faithfulness-пилот: две пары, приблизительно degree-matched контроли, **статистических выводов нет**. [Полные проверенные результаты](docs/VKR_STAGE3_DEPTH4_FAITHFULNESS_2026-11-10.md).

Следующие, **ещё не выполненные на реальных CSV**, режимы: `-Mode explanations-budget` (новый split=2062, повышенный поисковый бюджет) и `-Mode faithfulness-extended` (четыре пары и 20 контрольных удалений на пару). Все измерения новых режимов сохраняются отдельно и не заменяют завершённую серию 42 сравнений Node2Vec/TransE.

## Важное разграничение со старой версией

Репозиторий унаследовал от предыдущей курсовой/исследовательской работы файлы `src/convert.py`, `src/simple_node2vec.py`, `src/transe_runner.py`, `src/app.py`, `run_full_experiment.bat`, `requirements.txt`, а также старые `results/metrics` и `results/plots`. Они **не входят в актуальный подтверждённый конвейер ВКР**, могут использовать иной протокол оценки и не должны служить доказательством её нынешних результатов. 

Исходные данные и создаваемые в ходе новых запусков пользовательские оценки, модели и отчёты не публикуются. Автоматическая проверка проекта выполняется GitHub Actions на Python 3.11; браузерная проверка на компьютере получателя проводится отдельно.
